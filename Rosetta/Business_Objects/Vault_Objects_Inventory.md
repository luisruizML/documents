# Vault Objects Inventory

Every Hub, Link and Satellite of the [Business Objects](Index.md) pages, one table per object type, with the owner domain and the object added on the left. Generated from the pages by `build_inventory.py`; regenerate it whenever a page adds or changes a Vault object.

## Hubs

| **Owner domain** | **Object** | **Name** | **Definition** | **Grain** | **Business key** |
| --- | --- | --- | --- | --- | --- |
| Registries | Party | `hub_party` | The table that holds the identifier Nexus assigns to every party, whether it is a natural person or a legal entity. It is the one thing other objects point to when they mean "whoever owes or asks"; it carries no description of the party. | one row per business key | `party_bk`: a party identifier assigned by Nexus when a Natural Person or Legal Entity first becomes a party |
| Registries | Natural Person | `hub_natural_person` | The table that holds the identifier by which the source of record knows each individual person in the platform. It carries no description of the person; that is kept in the tables around it. | one row per business key | `natural_person_bk`: the internal person identifier of the source of record, set in the platform configuration. It is assigned once, never changed and never reused, so it stays unique for the life of the platform, and it is sized for everyone the State will ever register, not only today's population. It is not an identity document, and it cannot collide with a Legal Entity, which has its own Hub and its own keys |
| Registries | Legal Entity | `hub_legal_entity` | The table that holds the identifier by which the source of record knows each organization, association or collective recognized by the State: a registration or tax number for a formal entity, a registry code for an informal one. It carries no description of the entity. | one row per business key | `legal_entity_bk`: the identifier of the entity in the source of record, set in the platform configuration. It is usually a registration or tax number for a formal entity and a registry code for an informal one. It is assigned once, never changed and never reused, so it stays unique for the life of the platform, and it is sized for every entity the State will ever register. It cannot collide with a Natural Person, which has its own Hub and its own keys |
| Registries | Location | `hub_location` | The table that holds one identifier for each place the State refers to, whichever way the place is described: by a zone, by an address or by coordinates. It carries no description of the place. | one row per business key | `location_bk`: an identifier assigned by the platform when a place is first registered, never changed and never reused |
| Registries | Location | `hub_administrative_zone` | The table that holds the standard code by which the State knows each administrative zone, such as a province, a district or a ward, inside its jurisdiction. It carries no name of the zone. | one row per business key | `administrative_zone_bk`: the standard zone code, with the jurisdiction (country or territory) that owns it and the zone scheme |
| Registries | Location | `hub_address` | The table that holds the identifier by which the source of record knows each address. It carries no street, building or description. | one row per business key | `address_bk`: the identifier of the address in the source of record, or one assigned by the platform when the source has none |
| Registries | Location | `hub_geometry` | The table that holds the identifier of each surveyed shape, a point, a line or a polygon. It carries no coordinates, so a correction of the survey does not change the identifier. | one row per business key | `geometry_bk`: an identifier assigned by the platform when a shape is first registered, never changed and never reused |
| Platform | Code List | `hub_code_list` | The table that holds the name of each list of allowed values, such as gender, jurisdiction or key type. A new list is a new entry here, never a new table. | one row per business key | `code_list_bk`: the name of the list, such as `gender`. It is assigned once and never changed |
| Platform | Code List | `hub_code_value` | The table that holds each value that can appear in a list, identified by the list name and the code, such as gender:female. The same code in two lists is two different values. | one row per business key | `code_value_bk`: the list name and the code joined by a colon, such as `gender:female` |
| Platform | Load Configuration | `hub_load_configuration` | The table that holds each setting of how an attribute group is loaded for a jurisdiction, identified by the jurisdiction and the attribute group, with "any" for the default of every jurisdiction. It carries no choice itself; the choice is in `sat_load_configuration__mechanism`. | one row per business key | `load_configuration_bk`: the jurisdiction and the attribute group joined by a colon, such as `WSM:natural_person__demographics`. The jurisdiction is `any` for the default of every jurisdiction |

## Links

| **Owner domain** | **Object** | **Name** | **Definition** | **Grain** | **Business key** |
| --- | --- | --- | --- | --- | --- |
| Registries | Natural Person | `lnk_natural_person__party` | The table that places every natural person in the same universe as the legal entities, which together are the Parties. Any object that must point to "whoever owes or asks", of either kind, goes through the Party. | one row per distinct combination of natural person and party | `hub_natural_person`, `hub_party` |
| Registries | Natural Person | `lnk_natural_person__natural_person_relation` | The table that records that one person is related to another, such as spouses or a parent and a child. It says who is related; what the relationship is, and whether it still applies, is recorded in `sat_natural_person__natural_person_relation__relationship`. | one row per distinct combination of subject person and related person | `hub_natural_person` (subject), `hub_natural_person` (related) |
| Registries | Legal Entity | `lnk_legal_entity__party` | The table that places every legal entity in the same universe as the natural persons, which together are the Parties. It says that a legal entity is a party; who owns it is recorded in `lnk_legal_entity__party_owner`. | one row per distinct combination of legal entity and party | `hub_legal_entity`, `hub_party` |
| Registries | Legal Entity | `lnk_legal_entity__natural_person` | The table that records that a natural person acts for a legal entity, such as a director, a representative or a tribal chief. The role and the dates are recorded in `sat_legal_entity__natural_person__representation`. | one row per distinct combination of legal entity and natural person | `hub_legal_entity`, `hub_natural_person` |
| Registries | Legal Entity | `lnk_legal_entity__party_owner` | The table that records that a party owns a legal entity. The owner can be a natural person or another legal entity, and one entity can have many owners; the share and the state of each holding are recorded in `sat_legal_entity__party_owner__ownership`. It is not the identity table `lnk_legal_entity__party`. | one row per distinct combination of legal entity and owner party | `hub_legal_entity`, `hub_party` (owner) |
| Registries | Legal Entity | `lnk_legal_entity__legal_entity_hierarchy` | The table that records that one legal entity is a member of another, such as a company that belongs to a holding group. It says who groups whom; the kind of grouping and the period are recorded in `sat_legal_entity__legal_entity_hierarchy__membership`. It is a grouping and not ownership, which is recorded in `lnk_legal_entity__party_owner`. | one row per distinct combination of parent legal entity and member legal entity | `hub_legal_entity` (parent), `hub_legal_entity` (member) |
| Registries | Location | `lnk_administrative_zone__location` | The table that records that an administrative zone is one way a place is described. It makes the zone a Location, as `lnk_legal_entity__party` makes an entity a Party. | one row per distinct combination of administrative zone and location | `hub_administrative_zone`, `hub_location` |
| Registries | Location | `lnk_address__location` | The table that records that an address is one way a place is described. It makes the address a Location. | one row per distinct combination of address and location | `hub_address`, `hub_location` |
| Registries | Location | `lnk_geometry__location` | The table that records that a shape is one way a place is described. It makes the shape a Location. | one row per distinct combination of geometry and location | `hub_geometry`, `hub_location` |
| Registries | Location | `lnk_administrative_zone__administrative_zone_hierarchy` | The table that records that one administrative zone lies inside another, such as a ward inside a district. It says which zone contains which; the kind of division and the period are recorded in `sat_administrative_zone__administrative_zone_hierarchy__period`. | one row per distinct combination of parent administrative zone and member administrative zone | `hub_administrative_zone` (parent), `hub_administrative_zone` (member) |
| Registries | Location | `lnk_location__party` | The table that records that a place belongs to a party: where a natural person lives, where a legal entity is registered or operates. The role and the period are recorded in `sat_location__party__usage`. It is the way a place is attached to a person or an entity, and it is not the identity table `lnk_natural_person__party`. | one row per distinct combination of location and party | `hub_location`, `hub_party` |
| Platform | Code List | `lnk_code_list__code_value` | The table that records which values belong to which list. | one row per distinct combination of code list and code value | `hub_code_list`, `hub_code_value` |
